## Описание

Программа представляет собой сетевую викторину. Сервер отправляет клиенту вопросы с четырьмя вариантами ответов, проверяет ответы и подсчитывает набранные баллы. Клиент взаимодействует с сервером с помощью команд, позволяющих отвечать на вопросы, пропускать их, просматривать счёт и таблицу рекордов, а также начинать игру заново.

## Как собрать и запустить

Сборка проекта выполнялась в **Visual Studio 2022**.

Чтобы запустить, нужно:
1. Запустить `server.exe` в одном окне.
2. Запустить `client.exe` в другом окне.
3. В `client.exe` вводить команды. 

Сначала необходимо запустить сервер, так как клиент подключается к нему.

## Протокол

Сервер слушает порт 9000. Каждая команда передаётся одной строкой, после чего сервер отправляет одну строку ответа. После подключения сервер присылает приветственное сообщение.

| Команда | Что делает | Пример ответа |
|---|---|---|
| `A, B, C, D` | Отправить вариант ответа на вопрос | `Right! Next question: ...` |
| `SKIP` | Пропустить текущий вопрос | `Question skipped. Next question: ...` |
| `SCORE` | Показать текущий счёт | `Your score: 2` |
| `RESTART` | Начать викторину заново с перемешанными вопросами | `New game! Question 1/...` |
| `NAME Yujiudo` | Установить имя игрока | `Name set: Yujiudo` |
| `TOP` | Показать таблицу рекордов | `Leaderboard: Yujiudo - 5` |
| `QUIT` | завершить работу | `Goodbye!` |

## Ошибки

Если введена неправильная команда, сервер отправляет сообщение:

`Invalid command. Enter A, B, C, D or a command.`

Если викторина завершена, сервер отправляет сообщение:

`Quiz is finished. Enter RESTART to start a new game.`

Если вопросы не удалось загрузить из файла, сервер сообщает:

`Questions not loaded!`

Если игрок вводит пустое имя, сервер отправляет сообщение:

`ERROR. Enter a name.`

## Ответы на контрольные вопросы

**1. В каком порядке сервер вызывает socket, bind, listen, accept и что делает каждый вызов?**

Сервер вызывает функции в следующем порядке:

1. socket() — создаёт сокет, через который будет происходить обмен данными.
2. bind() — привязывает сокет к IP-адресу и порту 12345.
3. listen() — переводит сокет в режим ожидания подключений клиентов.
4. accept() — ожидает подключения клиента и принимает его. После этого создаётся отдельный сокет для общения с подключённым клиентом.

**2. Почему клиенту не нужны bind и listen? Какой порт получает клиент?**

Клиенту не нужно ждать подключения других устройств, поэтому ему не нужны bind() и listen(). Он просто подключается к серверу с помощью connect(). Система автоматически назначает клиенту свободный временный порт.

**3. Зачем нужен htons(PORT)?**

Функция htons() преобразует номер порта из порядка байтов компьютера в сетевой порядок байтов (Network Byte Order).

Это необходимо, чтобы устройства правильно понимали номер порта при сетевом обмене данными.

**4. Почему recvLine читает до символа \n, а не просто вызывает recv один раз?**

TCP передаёт данные в виде потока байтов и не сохраняет границы отдельных сообщений.

Поэтому один вызов recv() может получить только часть сообщения или сразу несколько сообщений. Функция recvLine() читает данные по одному символу до символа \n, чтобы получить полную строку сообщения.

**5. Опишите протокол своего варианта: какие команды, какие ответы, что сервер делает при ошибке?**

Сервер отправляет клиенту вопросы с четырьмя вариантами ответа: A, B, C и D. Клиент отправляет выбранную букву или одну из специальных команд.

Основные команды:

A, B, C, D — ответить на вопрос.

SKIP — пропустить вопрос.

SCORE — посмотреть текущий счёт.

RESTART — начать новую игру.

NAME Yujiudo — установить имя игрока.

TOP — посмотреть таблицу рекордов.

QUIT — завершить работу.

Сервер проверяет ответы и сообщает, правильный ответ или неправильный. За правильные ответы начисляются очки. После завершения викторины результат игрока сохраняется в файл records.txt.

Если введена неправильная команда, сервер отправляет сообщение:

`Ошибка. Введите A, B, C, D или команду.`

Если викторина завершена, сервер предлагает начать новую игру с помощью команды RESTART.
